# 数据与隐私（运营方视角）

这份文档是给**部署 AgentCode 的人**看的：你的服务器上到底存了用户什么数据、
存在哪、留多久、用户要删的时候会发生什么、以及你有哪些义务。

面向用户的那份是网页上的 `/privacy` 与 `/terms`（`agentcode/web/static/privacy.html`
和 `terms.html`）——**改动其中一份时，记得另一份也要跟着改**。

## 1. 数据清单

全部状态都在 `AGENTCODE_DATA` 这一个目录下（见 `docs/deploy.md`）：

| 数据 | 位置 | 里面是什么 | 敏感程度 |
| --- | --- | --- | --- |
| 账号 | `agentcode.db` → `accounts` | 用户名、PBKDF2-SHA256 加盐哈希、套餐、到期时间 | 高（身份） |
| 用量账本 | `agentcode.db` → `usage_ledger` | 每次运行用了多少 token、运行编号、时间 | 中 |
| 订单 | `agentcode.db` → `orders` | 套餐、金额、支付渠道与流水号 | 高（交易） |
| 会话 | `web-sessions/<账号id>/*.json` | 用户问的每一句话、智能体的每一个回答 | **高（内容）** |
| 代码工作目录 | `sandbox/<账号id>/` | 用户上传的文件、智能体生成的文件与测试 | **高（内容）** |
| 运行轨迹 | `traces/` | 每次运行的步骤与用量 | 中 |

两份内容是真正要小心的：**用户问的话**和**用户传的代码**。它们会：

- 落在这台服务器的磁盘上；
- **被发送给配置的大语言模型服务商**（见第 5 节）。

## 2. 留存策略

**默认：保留到用户主动删除。** 这是产品的默认值——
`AGENT_RETENTION_DAYS` 不配置就是 0，也就是永不自动清理。

如果法规或业务要求自动清理，配置一个天数：

```dotenv
# deploy/.env
AGENT_RETENTION_DAYS=90
```

行为：服务启动时扫一遍，之后每 24 小时扫一遍，删掉**超过该天数没动过**的
会话文件与代码文件（按文件修改时间判断），顺手收掉空目录。
**只删文件，不动账号、账本、订单**——那些是交易记录，不该被时间清掉。

改动前后记得在 `/privacy` 里同步说明，否则你写的是"保留到你主动删除"、
实际却在自动清理，那就是虚假陈述。

## 3. 用户要删的时候会发生什么

三个入口都在网页左下角「我的数据」里：

| 入口 | 接口 | 实际发生什么 |
| --- | --- | --- |
| 导出我的数据 | `GET /api/export` | 打包该账号的 `sessions` 与 `code` 目录成 zip，流式返回 |
| 清空代码目录 | `POST /api/account/purge-code` | 删 `sandbox/<账号id>/` 整个目录，会话保留 |
| 注销账号 | `POST /api/account/delete` | 删 `sandbox/<账号id>/`、`web-sessions/<账号id>/`，再从库里删掉账号、账本、订单 |

实现都在 `agentcode/lifecycle.py`，三条硬规则：

1. **只能删自己的**。所有函数都要求一个明确的 `account_id`；空 id 一律抛错，
   因为空 id 在别处表示"共享目录"（免登录本地模式），照着删就是把所有人的删了。
2. **先删文件，再删库记录**。万一中途失败，留下的是"账号还在、数据没了"
   （用户能再登进来看一眼、再删一次），而不是"账号没了、数据还在"
   ——后者用户自己再也处理不了。
3. **注销要输入用户名二次确认**。这种事没有撤销。

## 4. 你的义务

**改掉政策里的运营方信息。** `privacy.html` 和 `terms.html` 里现在写的是
「吴咏翰 / 824346648@qq.com」。如果你不是这个人，或者换了联系方式，
**必须先改**——政策上写着别人，等于没写。

**备份。** 现在没有任何自动备份。至少要定期把 `AGENTCODE_DATA` 打包存到别处：

```bash
tar czf agentcode-$(date +%F).tar.gz -C /srv/agentcode/data .
```

注意：备份里同样有用户的会话和代码，别随手丢在公共位置。

**数据泄露要能通知到人。** 这就是为什么账号表里要有可用的联系方式——
现在账号只有用户名，没有邮箱。真要做大，得补一个。

**别把 `AGENTCODE_DATA` 暴露到公网。** 它不在任何 HTTP 路由下，但
`docker-compose.yml` 里的卷映射和反向代理配置改动时容易误伤。

## 5. 第三方披露（最容易被忽略的一条）

用户的提问和智能体读到的文件内容**会发送给大语言模型服务商**
（DeepSeek / 通义 / 或你自己配的任何 OpenAI 兼容服务）。

这不是可写可不写的：用户有权知道他的话被发给了谁。

所以：

- `/privacy` 第二节里必须写明这一点（现在写了，但你要确认服务商名称与实际一致）；
- 如果你换了模型服务商，**政策要跟着改**；
- 如果服务商会把数据用于训练，那更要写清楚——很多合规要求专门盯这一条。

## 6. 还没有做的

诚实列一下，免得你以为已经齐了：

| 缺什么 | 影响 |
| --- | --- |
| 账号没有邮箱字段 | 无法主动通知用户（数据泄露、服务变更），只能靠用户在网页上看到 |
| 没有操作审计日志 | "谁在什么时候删了什么"查不到；出纠纷时说不清 |
| 没有软删除/回收站 | 点了删除就真没了，用户误操作找不回来 |
| 没有数据出境评估 | 如果模型服务商在境外，涉及数据出境合规 |
| 没有备案 | 国内面向公众提供服务需要 ICP 备案，见 `docs/deploy.md` |
